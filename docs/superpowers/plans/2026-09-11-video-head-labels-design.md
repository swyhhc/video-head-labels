# 视频头顶加字幕 — V1 产品与技术规格

日期：2026-09-10  
状态：待用户最终确认  
项目代号：视频头顶加字幕  
建议 GitHub 仓库名：`video-head-labels`

---

## 1. 产品定义

一个完全在浏览器本地运行的 AI 动态标签视频工具。

用户导入一段短视频后，系统自动检测并追踪画面中的多个主体，为每个主体生成一个会跟随移动的动态姓名牌。用户可以修改名称、隐藏主体、纠正跟踪错误，并在本地导出最终 MP4。

V1 的核心优先级：

1. 主体找得准
2. 身份跟得稳
3. 标签看起来稳、不抖、不乱
4. 出错后用户能快速修正
5. 全程本地处理，不上传视频，不依赖后端

---

## 2. V1 核心工作流

导入视频  
→ 读取视频信息  
→ 检查编码兼容性  
→ 必要时本地转码  
→ 本地目标检测  
→ 多目标追踪  
→ ReID 辅助身份恢复  
→ 生成 Track 数据  
→ 用户改名 / 隐藏 / 修正  
→ Canvas 实时预览  
→ 本地逐帧渲染  
→ ffmpeg.wasm 编码  
→ 导出 MP4

## 4. 技术原则

### 4.1 V1 不做后端

V1 为纯前端、本地运行产品：

- 视频不上传服务器
- AI 推理在本地浏览器完成
- 追踪在本地完成
- ReID 在本地完成
- 转码在本地完成
- 导出在本地完成

### 4.2 保持模块边界

虽然 V1 不做后端，但核心模块不能与 UI 写死。

至少保持以下抽象：

- `MediaPreprocessor`
- `Detector`
- `Tracker`
- `Renderer`
- `Exporter`

V1 实现：

- `BrowserMediaPreprocessor`
- `BrowserDetector`
- `BrowserTracker`
- `CanvasRenderer`
- `BrowserExporter`

未来如果真的需要云端，只替换底层实现，不重写编辑器。

## 5. 技术栈

### 前端框架

- Next.js
- React
- TypeScript

### 视频播放

- `HTMLVideoElement`

### 标签和编辑层

- Canvas

### 本地 AI 推理

- ONNX Runtime Web
- 优先 WebGPU
- 不支持 WebGPU 时回退 WASM

### 目标检测

- 轻量 YOLO ONNX 模型
- 具体版本不在 Spec 阶段写死
- 实现前通过 benchmark 决定模型

### 多目标追踪

参考：

- ByteTrack
- BoT-SORT

但项目内部使用自有 `Tracker` 接口，不将业务逻辑绑定到具体算法。

### ReID

使用轻量外观特征模型，为交叉、遮挡、短暂消失后的身份恢复提供辅助。

### 视频转码与导出

- `ffmpeg.wasm`

### 并发与性能

- AI 推理放入 Web Worker
- 避免阻塞 UI 主线程
- 模型与编辑器状态解耦

## 6. 视频输入约束

初始推荐配置：

| 参数 | V1 |
|---|---|
| 推荐时长 | ≤ 15 秒 |
| 目标支持 | ≤ 30 秒 |
| 最大分辨率 | 1920 × 1080 |
| 最大帧率 | 30 fps |
| 推荐文件大小 | ≤ 50 MB |
| 初始硬上限 | 100 MB |
| 后续测试上限 | 200 MB |
| 推荐编码 | H.264 |
| HEVC | 支持识别和必要时转换 |
| 输出格式 | MP4 |

所有阈值必须放在统一配置文件中，不允许散落硬编码。

最终是否开放 30 秒 / 200MB，必须根据性能压测决定。

## 7. 视频预处理

导入视频后先执行媒体检查：

1. 获取时长
2. 获取分辨率
3. 获取帧率
4. 获取容器格式
5. 获取编码信息
6. 检查浏览器原生解码能力
7. 检查 WebGPU / WASM 能力
8. 判断是否需要转码

### HEVC 处理策略

- 能稳定直接处理：不转码
- 后续处理链不兼容：本地转 H.264
- 转码时必须展示进度
- 转码失败不得丢失当前项目状态

---

## 8. 目标检测策略

目标检测不要求每一帧执行。

基础策略：

- 间隔若干帧运行检测
- 中间帧由 Tracker 推断
- 运动剧烈时提升检测频率
- 场景稳定时降低检测频率

目标：

在稳定性和本地性能之间取得平衡。

检测输出至少包括：

- bbox
- category
- confidence
- timestamp / frameIndex

---

## 9. 多目标追踪要求

每个主体拥有唯一 `trackId`。

示例：

- `track_001`
- `track_002`
- `track_003`

两只同类鸟也必须保持不同 Track。

追踪关联需要综合：

- 检测框重合度
- 位置
- 速度
- 运动方向
- 历史轨迹
- ReID 外观特征

不能只使用“离得最近”作为身份关联依据。

---

## 10. Track 生命周期

Track 至少支持以下状态：

- `new`
- `active`
- `temporarily_lost`
- `reidentified`
- `ended`

主体短暂消失时：

`active → temporarily_lost → reidentified → active`

不能因为短暂漏检就立即创建新的 Track。

---

## 11. 主体数量

V1：

- 同时最多维护 10 个 Track
- 推荐舒适范围：1–6 个主体

如果画面中出现大量对象，不要求全部生成最终标签。

后续可根据以下指标筛选：

- 主体面积
- 存在时长
- 检测置信度
- 用户主动选择

---

## 12. Track 数据结构

概念模型：

```ts
interface Track {
  id: string;
  category: string;
  confidence: number;
  labelZh: string;
  labelEn?: string;
  visible: boolean;
  state: TrackState;
  trajectory: TrackPoint[];
  appearanceEmbedding?: number[];
}
```

AI 类别与用户名称必须分离。

例如：

- AI 类别：`bird`
- 中文名称：`麻雀`
- 英文名称：`Tree Sparrow`

用户改名不影响内部识别类别。

---

## 13. 人工纠错

### 改名

用户可以修改：

- 中文名称
- 英文名称

### 隐藏

用户可以关闭某个 Track 的最终显示。

### 重新绑定

当标签跟丢时：

用户在当前时间点重新点击正确主体，系统从当前时间点之后重新绑定。

### 身份修正

当两个主体交叉后串 ID：

用户选择“身份跟错”，再指定正确主体，系统从当前时间点重建后续身份关联。

### 优先级

人工修正优先于 AI 自动判断。

AI 可以提示异常，但不能偷偷覆盖人工绑定。

---

## 14. 标签视觉

默认结构：

中文名称  
英文名称  
细引导线  
主体锚点

### 默认视觉规则

- 中文为主标题
- 英文为次标题
- 英文字号约为中文的 45%–55%
- 默认白色文字
- 允许轻微描边或阴影提升复杂背景可读性
- 引导线细
- 默认标签位置在主体上方
- 上方空间不足时自动尝试其他位置

候选位置：

- 上方
- 左上
- 右上
- 左侧
- 右侧

---

## 15. 标签样式

V1 仅支持三套预设：

### 经典

中文 + 英文 + 引导线

### 极简

仅中文

### 数据感

中文 + 英文 + 类别 / 置信度

正式导出默认使用经典模式。

---

## 16. 标签平滑

检测框坐标和标签显示坐标必须分离。

标签位置需要独立平滑处理，避免：

- 轻微抖动
- 高频跳动
- 主体静止时标签仍不停移动

最终视觉目标：

“标签黏在主体附近”。

---

## 17. 多标签避让

多个标签不能直接重叠。

碰撞时按优先级处理：

1. 上下错位
2. 左右偏移
3. 延长引导线
4. 使用备用候选位置

标签移动后，引导线必须仍然准确指向对应主体。

---

桌面 V1 建议结构：

### 主区域

视频预览 + Canvas 标签层

### 时间轴

- 播放 / 暂停
- 拖动
- 小步移动
- Track 存在区间

### 主体面板

编辑模式允许显示：

- 检测框
- Track ID
- 轨迹
- 置信度
- Track 状态
- 当前选中状态

## 20. 项目数据层

编辑器不得把所有项目数据直接塞进 React 组件状态。

独立 Project 模型至少包含：

```ts
interface Project {
  video: VideoMeta;
  tracks: Track[];
  manualCorrections: ManualCorrection[];
  styleConfig: StyleConfig;
  exportConfig: ExportConfig;
}
```

这样以后可以自然增加：

- Undo / Redo
- 项目保存
- 项目恢复
- 本地持久化
- 云端同步

V1 不要求全部实现，但结构不能阻碍未来增加。

---

## 21. 导出流程

用户点击导出后：

1. 锁定当前 Project State
2. 按原始时间顺序逐帧读取视频
3. 根据时间获取 Track 坐标
4. 计算标签平滑位置
5. 执行标签避让
6. Canvas 合成原视频帧和标签
7. 输出合成帧
8. ffmpeg.wasm 编码
9. 导出 MP4

导出结果只包含：

- 原视频
- 用户最终标签

---

## 22. 错误处理

必须针对具体错误给出明确提示。

### 视频过长

提示用户裁剪。

### 文件过大

提示当前本地版本限制。

### 编码不兼容

尝试本地转码。

### HEVC 无法解析

转换为 H.264。

### WebGPU 不可用

自动回退 WASM。

### 内存不足

提示降低：

- 时长
- 分辨率
- 文件大小

### AI 初始化失败

展示具体错误，不只显示“处理失败”。

### 导出失败

保留项目和用户编辑结果。

### 未识别到主体

允许用户手动指定主体，不得让流程直接结束。

---

## 23. 隐私

V1 核心产品原则：

**视频不上传服务器。**

所有处理均发生在本地：

- 解码
- 转码
- AI 检测
- 多目标追踪
- ReID
- 编辑
- 导出

页面应明确提示：

“视频仅在本地处理，不会上传。”

---

## 24. 移动端兼容预留

V1 桌面优先，但代码和交互设计不得阻碍后续移动端适配。

必须遵守：

- 核心功能不能依赖 hover
- 所有重要操作可通过点击 / 触控完成
- Canvas 使用独立视频坐标系，不写死屏幕像素
- 编辑数据与布局解耦
- 时间轴逻辑与桌面布局解耦
- 主体编辑操作可迁移到抽屉 / 底部面板
- 视频处理模块不得依赖桌面专属 API

未来手机端仍优先尝试纯本地处理。

如果性能不足，再通过：

- 降低分辨率
- 降低时长
- 降低主体数
- 降低检测频率
- 降低 ReID 强度

进行设备级降级。

云端推理不属于当前产品路线。

## 26. V1 验收标准

V1 至少满足：

- 成功导入普通 H.264 视频
- 成功识别 HEVC 视频
- 必要时成功完成 HEVC 本地转码
- 同时追踪至少 5 个主体
- 同类主体拥有不同 ID
- 普通短暂遮挡后尽量恢复原身份
- 两主体交叉后大部分情况下不串 ID
- 漏检几帧后 Track 不立即消失
- 串 ID 后可人工修正
- 标签位置稳定
- 多标签可自动避让
- 支持修改中英文名称
- 支持隐藏主体
- 支持重新绑定
- 支持本地导出 MP4
- 导出结果与预览视觉基本一致
- 导出不包含检测框 / Track ID / 轨迹
- 整个流程无服务器依赖

## 28. 开发原则

1. 先验证最危险的技术点，再做漂亮 UI。
2. 模型、追踪器、导出器必须可替换。
3. 不为未来假想需求提前建设后端。
4. 所有性能限制必须配置化。
5. 任何 AI 错误都应该有人工兜底。
6. 编辑预览和最终导出必须使用同一套 Renderer 逻辑。
7. 桌面优先，但不得写出阻碍移动端的交互和坐标系统。
8. 所有用户视频默认仅存在本地内存 / 浏览器本地环境，不上传。

## 30. 当前架构决策

已确认：

- V1 纯本地
- 不做云端推理
- 不做后端
- 桌面电脑先用
- 后续希望可以适配手机
- 多主体支持
- 追踪稳定性优先
- 引入 ReID 作为增强
- 支持 HEVC 识别与必要时本地转码
- 支持本地 MP4 导出
- 初期推荐 15 秒，目标 30 秒
- 时长、文件大小等限制全部配置化
